# OS Advanced Topics — Deadlock, Threading, File Systems

Comprehensive definitions covering OS architecture, system calls, threads, process synchronization, deadlock, file systems, disk management, I/O, and security.

## 3. Operating System Architecture

| Architecture | Description | Examples |
|---|---|---|
| **Monolithic Kernel** | Entire OS runs in kernel space; all services in one binary | Linux, Unix, MS-DOS |
| **Layered Architecture** | OS divided into layers; each layer uses services from lower layer | THE system |
| **Microkernel** | Minimal kernel; most services run in user space | Minix, QNX, macOS (XNU) |
| **Modular Kernel** | Kernel loads/unloads modules at runtime | Linux (loadable kernel modules) |
| **Hybrid Kernel** | Combines microkernel and monolithic approaches | Windows NT, macOS |
| **Virtual Machine** | Provides abstraction of complete hardware; multiple OSes on same host | VMware, VirtualBox |
| **Client-Server Architecture** | Services run as user-space servers; kernel handles IPC | Minix, early Windows NT |

### Monolithic vs Microkernel

| Aspect | Monolithic | Microkernel |
|---|---|---|
| Size | Large | Small |
| Performance | Fast (direct calls) | Slower (IPC overhead) |
| Debugging | Harder | Easier |
| Extensibility | Recompile needed | Modules can be added |
| Fault Isolation | Low (one crash = system crash) | High (services can restart) |

## 4. System Calls ⭐

### Definition
**System Calls** are the interface between user programs and the OS kernel. They provide a controlled way for user-mode programs to request kernel-mode services (hardware access, process creation, memory allocation).

### Purpose
- Provide a **protected interface** to hardware
- Allow user programs to perform **privileged operations**
- Maintain **system stability and security** by controlling access

### Types of System Calls

| Type | Examples | Functions |
|---|---|---|
| **Process Control** | `fork()`, `exec()`, `exit()`, `wait()` | Create, terminate, control processes |
| **File Management** | `open()`, `read()`, `write()`, `close()`, `delete()` | Create, read, write, delete files |
| **Device Management** | `ioctl()`, `read()`, `write()` | Request device operations |
| **Information Maintenance** | `getpid()`, `alarm()`, `sleep()`, `time()` | Get/set system data |
| **Communication** | `pipe()`, `shmget()`, `socket()`, `send()` | Inter-process communication |
| **Protection** | `chmod()`, `chown()`, `umask()` | Set file permissions, ownership |

## 6. Threads ⭐

### Definition
A **thread** is the smallest unit of execution within a process. A process can have multiple threads that share the same memory space and resources but execute independently.

### Process vs Thread

| Aspect | Process | Thread |
|---|---|---|
| Definition | Program in execution | Unit of execution within a process |
| Memory Space | Separate | Shared with process threads |
| Context Switching | Slower (heavier) | Faster (lighter) |
| Communication | IPC required (slower) | Direct memory access (faster) |
| Resource Overhead | High | Low |
| Crash Impact | Independent | Can crash entire process |

### User-Level Thread vs Kernel-Level Thread

| Aspect | User-Level Thread | Kernel-Level Thread |
|---|---|---|
| Managed by | User-space thread library | OS kernel |
| Context Switch | Very fast (no kernel involvement) | Slower (kernel involvement) |
| Blocking | One blocking thread blocks all threads in process | Only the blocking thread blocks |
| Parallelism | Cannot utilize multiple cores | Can utilize multiple cores |
| Examples | POSIX Pthreads (user mode), Java threads | Windows threads, Linux threads |

### Multithreading
The ability of a CPU or a process to execute multiple threads concurrently. Benefits include **improved responsiveness**, **resource sharing**, **economy** (cheaper than processes), and **scalability** (multi-core utilization).

### Advantages of Multithreading
1. **Responsiveness** — UI remains responsive during background processing
2. **Resource Sharing** — Threads share memory and resources of the process
3. **Economy** — Creating and switching threads is cheaper than processes
4. **Scalability** — Threads can run in parallel on multiple cores

## 8. Process Synchronization ⭐

### Critical Section
A **critical section** is a segment of code that accesses **shared resources** (variables, files, devices) that must not be executed by more than one process at a time. Requirements:
- **Mutual Exclusion** — Only one process in critical section at a time
- **Progress** — If no process is in CS, a waiting process must be able to enter
- **Bounded Waiting** — A process must not wait indefinitely

### Race Condition
A **race condition** occurs when multiple processes access and manipulate shared data concurrently, and the outcome depends on the order of execution. This leads to **inconsistent results**.

### Mutual Exclusion
Ensuring that only one process at a time can execute in the critical section. Mechanisms include **software** (Peterson's, Dekker's) and **hardware** (test-and-set, swap) approaches.

### Semaphore
A **semaphore** is an integer variable accessed through two atomic operations: `wait()` (P) and `signal()` (V).
- **Binary Semaphore** — Values 0 or 1 (like a mutex)
- **Counting Semaphore** — Values 0 to N (manages multiple resources)

### Mutex
A **mutex (mutual exclusion)** is a locking mechanism that allows only one thread to access a resource at a time. Unlike a semaphore:
- A mutex has ownership (only the locking thread can unlock)
- Simpler to use for mutual exclusion

### Monitor
A **monitor** is a high-level synchronization construct that:
- Groups shared data and procedures into a single unit
- Ensures only one thread can execute inside the monitor at a time
- Java's `synchronized` keyword implements monitor-like behavior

### Peterson's Algorithm
A software-based solution for mutual exclusion between two processes:
```
flag[i] = true;
turn = j;
while (flag[j] && turn == j);
    // critical section
flag[i] = false;
```

### Classical Synchronization Problems

| Problem | Description |
|---|---|
| **Producer-Consumer** | Producer creates data, consumer uses it; bounded buffer prevents overflow/underflow |
| **Reader-Writer** | Multiple readers can access simultaneously; writer needs exclusive access |
| **Dining Philosopher** | 5 philosophers share 5 forks; must eat without deadlock |

## 9. Deadlock ⭐

### Definition
A **deadlock** is a situation where two or more competing processes are each waiting for the other to release a resource, causing all of them to be blocked indefinitely.

### Necessary Conditions (ALL must hold)
| Condition | Description |
|---|---|
| **Mutual Exclusion** | At least one resource is non-shareable |
| **Hold and Wait** | Process holds a resource while waiting for another |
| **No Preemption** | Resources cannot be forcibly taken from a process |
| **Circular Wait** | A circular chain of processes, each waiting for a resource held by the next |

### Resource Allocation Graph (RAG)
A directed graph showing:
- **Processes** (circles) → Requesting resources
- **Resources** (rectangles) → Held by processes
- A **cycle** in RAG indicates possible deadlock (if only one instance per resource, cycle = deadlock)

### Deadlock Prevention
Prevent at least one of the four conditions:
- **Mutual Exclusion** → Not possible for non-shareable resources
- **Hold and Wait** → Process must request all resources at once
- **No Preemption** → Preempt resources from waiting processes
- **Circular Wait** → Impose a total ordering of resource types

### Deadlock Avoidance
The OS decides whether allocating a resource will lead to a **safe state**.

**Banker's Algorithm ⭐**
The Banker's Algorithm is used for deadlock avoidance. It checks if granting a resource request leaves the system in a **safe state** (where all processes can eventually complete).
- Each process declares maximum resource needs
- OS allocates only if safe state is maintained
- **Safety Algorithm** checks if a safe sequence exists

### Deadlock Detection
- Allow deadlock to occur, then detect it
- Use **Wait-For Graph** (simplified RAG)
- If cycle detected → deadlock exists

### Recovery from Deadlock
- **Process Termination** — Kill one or more deadlocked processes
- **Resource Preemption** — Take resources from some processes and give to others
- **Rollback** — Roll back processes to a safe state and restart

## 14. File System ⭐

### File
A **file** is a named collection of related data stored on secondary storage. It is the smallest logical unit of data storage.

### Directory
A **directory** is a container that stores files and other directories (subdirectories), forming a hierarchical structure.

### File Attributes
- **Name** — Human-readable identifier
- **Type** — Text, binary, executable, etc.
- **Location** — Pointer to location on disk
- **Size** — Current file size in bytes
- **Protection** — Read/write/execute permissions
- **Timestamp** — Creation, modification, access times

### File Operations
- **Create** — Allocate space and directory entry
- **Open** — Load file metadata into memory
- **Read** — Read data from file at current position
- **Write** — Write data to file at current position
- **Close** — Flush data and free memory
- **Delete** — Free space and remove directory entry
- **Seek** — Reposition the file pointer

### File Types
- **Regular Files** — Text, source code, binaries
- **Directories** — Contain file entries
- **Special Files** — Device files (block/character)
- **Links** — Hard links and symbolic (soft) links

### Access Methods
| Method | Description | Examples |
|---|---|---|
| **Sequential** | Data accessed in order, from beginning | Magnetic tapes |
| **Direct (Random)** | Data accessed directly by block number | Disks |
| **Indexed** | Index points to data blocks | Database files |

### Directory Structures

| Structure | Description | Pros/Cons |
|---|---|---|
| **Single Level** | All files in one directory | Simple; naming conflicts |
| **Two Level** | Separate directory for each user | User isolation; no subdirectories |
| **Tree** | Hierarchical; directories within directories | Most common; flexible |
| **Acyclic Graph** | Tree with shared files (links) | Shared access; need garbage collection |

### Allocation Methods

| Method | Description | Pros/Cons |
|---|---|---|
| **Contiguous** | File occupies consecutive blocks | Fast access; external fragmentation |
| **Linked** | Each block points to next block | No fragmentation; slow random access |
| **Indexed** | Index block points to all data blocks | Fast random access; index overhead |

### Free Space Management
- **Bit Vector** — Each block represented by a bit (1=free, 0=allocated)
- **Linked List** — Free blocks linked together
- **Grouping** — First free block points to group of free blocks
- **Counting** — Store address of first free block and count of consecutive blocks

## 15. Disk Management ⭐

### Disk Scheduling
The OS must schedule disk I/O requests to minimize **seek time** (time for read/write head to reach the correct track).

### Disk Scheduling Algorithms

| Algorithm | Description | Characteristics |
|---|---|---|
| **FCFS** | Requests served in arrival order | Simple; poor performance (no optimization) |
| **SSTF** (Shortest Seek Time First) | Closest request served first | Better performance; starvation possible |
| **SCAN (Elevator)** | Head moves in one direction, serving requests; reverses at end | Fair; no starvation |
| **C-SCAN** (Circular SCAN) | Head serves in one direction only; jumps back to start | Uniform wait time |
| **LOOK** | SCAN but reverses only when no more requests in current direction | More efficient than SCAN |
| **C-LOOK** | C-SCAN but reverses only when no more requests in current direction | Most efficient |

## 16. I/O System

| Concept | Description |
|---|---|
| **Interrupt** | Signal from hardware/software that CPU should suspend current task and handle the event |
| **DMA** (Direct Memory Access) | Allows hardware to access main memory directly without CPU involvement; speeds up data transfer |
| **Polling** | CPU repeatedly checks device status; wastes CPU cycles |
| **Buffering** | Temporary storage area to smooth data transfer between devices with different speeds |
| **Caching** | Stores frequently accessed data in faster memory for quick retrieval |
| **Spooling** | Overlapping I/O of one job with computation of other jobs using a shared buffer (e.g., print spooler) |

### Buffering vs Caching

| Aspect | Buffering | Caching |
|---|---|---|
| Purpose | Speed matching between devices | Reduce access time by storing frequently used data |
| Data Nature | Temporary holding; data consumed exactly once | Retained for reuse |
| Location | Main memory or dedicated buffer | Cache memory (L1/L2/L3) |
| Example | Print buffer, network buffer | CPU cache, DNS cache |

### Spooling vs Buffering

| Aspect | Spooling | Buffering |
|---|---|---|
| Scope | Overlaps I/O of one job with computation of another | Overlaps I/O of one job with its own computation |
| Data | Data stays until consumed (e.g., entire print job) | Data is temporary (e.g., one block) |
| Hold | Can hold data for extended periods | Short-term holding only |
| Example | Print spooler | Keyboard input buffer |

## 17. Protection and Security

| Concept | Description |
|---|---|
| **Authentication** | Verifies user identity (password, biometrics, OTP) |
| **Authorization** | Determines what an authenticated user can access |
| **Access Matrix** | Rows = domains, Columns = objects; cells contain access rights |
| **Access Control List (ACL)** | Lists users and their permissions for each object (column-based) |
| **Capabilities** | Lists objects and permissible operations for each domain (row-based) |
| **User Privileges** | Levels of access granted to users (admin, standard, guest) |
| **File Permissions** | Read (r), Write (w), Execute (x) for Owner, Group, Others |
| **Password Security** | Hashing, salting, minimum complexity, expiration policies |

### Types of Malware

| Type | Description | Propagation |
|---|---|---|
| **Virus** | Attaches to host program; replicates when program runs | File infection, removable media |
| **Worm** | Self-replicating; spreads without host program | Network, email |
| **Trojan Horse** | Disguised as legitimate software; performs malicious actions | Download, social engineering |
