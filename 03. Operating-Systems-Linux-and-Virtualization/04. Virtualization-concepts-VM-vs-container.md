# Virtualization Concepts — VM vs. Container

Comprehensive definitions of virtualization technology, hypervisors, virtual machines, containers, and cloud computing basics.

---

## 20. Virtualization

### Definition
**Virtualization** is a technology that allows creating a virtual (software-based) version of a computing resource — such as a server, storage device, network, or operating system. It enables running multiple virtual environments on a single physical hardware.

### Hypervisor
A **hypervisor** (Virtual Machine Monitor / VMM) is software that creates and runs virtual machines. It separates the physical hardware from the virtual environments.

#### Type 1 Hypervisor (Bare Metal)
- Runs **directly on physical hardware**
- No host OS required
- Better performance and security
- **Examples:** VMware ESXi, Microsoft Hyper-V, Xen, KVM

#### Type 2 Hypervisor (Hosted)
- Runs **on top of a host operating system**
- Easier setup; good for testing/development
- Slightly higher overhead
- **Examples:** Oracle VirtualBox, VMware Workstation, Parallels Desktop

For detailed comparison, see the dedicated file: `05. Type-1-vs-Type-2-Hypervisor.md`

### Virtual Machine (VM)
A **Virtual Machine** is a software-based emulation of a physical computer. Each VM includes:
- **Guest OS** — The operating system running inside the VM
- **Virtual Hardware** — Virtual CPU, RAM, disk, network adapter
- **Hypervisor** — Provides hardware abstraction

**Characteristics of VMs:**
- Full isolation between VMs (strong security boundary)
- Each VM runs its own complete OS (can be different from host)
- Heavier resource usage (each OS has its own kernel, drivers, services)
- Slower boot time compared to containers

### Containers (Basic Concept)
A **container** is a lightweight, standalone, executable package that includes everything needed to run a piece of software: code, runtime, system tools, libraries, and settings.

**Characteristics of Containers:**
- **Share host OS kernel** — All containers on a host share the same kernel
- **Lightweight** — No full OS overhead; only application and dependencies
- **Fast startup** — Containers start in seconds (vs. minutes for VMs)
- **Portable** — Run consistently across different environments
- **Isolation** — Process and filesystem isolation (but weaker than VMs)

### Docker (Basic Idea)
**Docker** is a platform for developing, shipping, and running applications in containers.
- **Docker Image** — Read-only template with instructions for creating a container
- **Docker Container** — Runnable instance of a Docker image
- **Docker Hub** — Public registry for sharing container images
- **Dockerfile** — Text file with instructions to build a Docker image

### VM vs Container Comparison

| Aspect | Virtual Machine | Container |
|---|---|---|
| **Architecture** | Full OS per VM | Shares host OS kernel |
| **Size** | GBs (full OS + app) | MBs (app + dependencies only) |
| **Boot Time** | Minutes | Seconds |
| **Performance** | Near-native (some overhead) | Near-native (minimal overhead) |
| **Isolation** | Strong (hardware-level) | Moderate (process-level) |
| **Resource Usage** | Higher | Lower |
| **Portability** | Good (OVF/OVA formats) | Excellent (OCI images) |
| **Use Case** | Full OS environments, legacy apps | Microservices, cloud-native apps |

## 21. Cloud Computing (Basic)

### Definition
**Cloud Computing** is the on-demand availability of computing resources (servers, storage, databases, networking, software) over the internet, with pay-as-you-go pricing.

### Service Models

| Model | Description | What You Manage | Example |
|---|---|---|---|
| **IaaS** (Infrastructure as a Service) | Virtualized computing resources (VMs, storage, networks) | Apps, data, runtime, middleware, OS | AWS EC2, Google Compute Engine, Azure VMs |
| **PaaS** (Platform as a Service) | Platform to develop, run, and manage apps | Apps and data only | Heroku, Google App Engine, AWS Elastic Beanstalk |
| **SaaS** (Software as a Service) | Ready-to-use software accessed via browser | Nothing (just use the app) | Gmail, Google Docs, Microsoft 365, Salesforce |

### Virtualization Relation to Cloud
- Virtualization is the **foundational technology** that enables cloud computing
- Cloud computing uses virtualization to pool and abstract physical resources
- A cloud provider operates large-scale virtualized data centers
- Users provision virtual machines or containers on demand

### Cloud Deployment Models
| Model | Description |
|---|---|
| **Public Cloud** | Resources owned and operated by third-party provider; accessible over internet |
| **Private Cloud** | Resources used exclusively by one organization; more control |
| **Hybrid Cloud** | Combination of public and private clouds; data/apps can be shared |
